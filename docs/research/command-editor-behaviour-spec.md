## 3. Documented behaviours to reproduce (functional)
Warp-documented (S1,S2): click-to-place cursor; multi-line editing with soft wrap; copy/cut/paste; select by char/word/line/all; word and line-boundary movement (Home/End, Ctrl+A/E); delete word/line/to cursor; optional auto-pair of quotes/brackets; Esc closes suggestion/history menu; triple-click selects logical (not visual) line; Vim keybindings optional; works over SSH. Blocks group each command+output; copy command/output separately; jump to output start; re-input a prior command; bookmark; find/filter in blocks; sticky command header.
Nexus-specific additions come from kit spec (S9): Shift+Enter newline, Run button for multiline/privileged, undo/redo, find/replace in draft, paste review, a11y, 1.3x scaling.

## 4. Behaviour requirements (BR)
- BR-1 Click anywhere in a draft (incl. 300+ chars, soft-wrapped) places the caret there. Clicking never executes or modifies submitted blocks.
- BR-2 Enter submits when safe; Shift+Enter newline (configurable); multiline/elevated drafts require explicit Run/confirm.
- BR-3 Editor undo/redo are draft-local and do not touch the PTY.
- BR-4 Soft wrap is visual only; the submitted text has no inserted newlines.
- BR-5 Paste: strip/reject C0/C1 control and ESC sequences except \n and \t; normalise CRLF and lone `\r` to `\n` (a pasted `\r` is never sent raw because it would execute); flag (do not silently strip) bidi controls U+202A–202E and U+2066–2069, zero-width/invisible characters (U+200B–200F, U+2060, U+FEFF) and mixed-script homoglyphs (Trojan Source class); show raw preview with escapes and flagged characters made visible; never auto-run.
- BR-6 Byte-exact framing. Single-line draft: draft bytes + `\r` (Enter is `\r`, never `\n`). Multiline draft when bracketed paste is active: `ESC[200~` + draft (with `\n` between lines) + `ESC[201~` + `\r`. Because readline may emit `?2004h` before `B` (inference, unrun) and prompt content can inject escapes between `A` and `B`, the preferred source is the integration reporting paste capability on the authenticated side channel (BR-15); TC-04/TC-25 first verify byte ordering per shell. Fallback observation of bracketed-paste state: the connector's own parser tracks DECSET/DECRST 2004 **only from the PTY stream while in INPUT state (after `B`, before `C`)**, with the value reset to off at each `A`; output from RUNNING state never changes it. If state is off or unknown, multiline drafts are sent line by line, each requiring confirmation. No `sh -c` wrapper, no quoting changes. Any `ESC[201~` in the draft is removed under BR-5 before framing.
- BR-7 One long-lived PTY; `cd`/exports persist across submissions.
- BR-8 Block = {id, command, cwd, host/user, start, end, exit code, output cursor}. Block boundaries come only from verified OSC 133 markers emitted by Nexus's opt-in integration; output text can't forge them (see BR-12).
- BR-9 Block actions: Copy command, Copy output, Edit as draft (never auto-run), Rerun (confirm if destructive or cross-host), Share redacted, attach to issue.
- BR-10 Unknown shell / no markers → block grouping disabled, editor falls back to raw PTY with manual toggle.
- BR-11 Unsent draft survives disconnect/refresh and is never auto-submitted after reconnect.
- BR-12 Marker authentication `[INFERENCE: OSC 133 has no nonce; VS Code's OSC 633;E nonce (S10) is the nearest prior art]`. The integration puts a random nonce (>=128 bit) in each marker's params; the parser drops markers without a valid nonce, bounds buffers, and rejects unknown OSC from untrusted output for HTML/links.
  - Defends against: passive content (`cat`, `curl`, logs, MOTD, file contents) that does not know the nonce.
  - Does NOT defend against: programs the user runs that can read the shell environment, and anything that can read the terminal's own earlier output.
  - Required: (a) nonce held in a **non-exported** shell variable (never in the environment of children; verify `env` and `/proc/<pid>/environ` of a child lack it; note `set` in the same shell can print it, so the integration unsets/hides it from `set` output where the shell allows, else documents residual risk); (b) the connector strips nonce-bearing marker bytes from rendered output, scrollback, block records, shared/redacted output and Paperclip attachments; (c0) delivery of the initial nonce: the connector writes it to a 0600 file in the 0700 session dir over the authenticated exec channel; the integration reads it into a non-exported variable and deletes the file; it is never typed into the PTY (would echo into scrollback/tmux history); (c) rotate per session at minimum, per prompt where the shell allows (nonce for the next prompt is delivered on the side channel of BR-15 or in the prior authenticated `D`); (d) a marker with a previously used or expired nonce is ignored and logged (replay of a nonce leaked from earlier output yields no block).
- BR-14 Terminal response-injection class. OSC 52 clipboard **read** is always denied; OSC 52 **write** is off by default and requires per-session user consent. Responses to queries (DA/DSR/CPR, `CSI 21 t` title report, DECRQSS, OSC 10/11 colour queries) must never contain attacker-controlled bytes (titles, text from the stream) and are generated only by the terminal core, never echoed from output into PTY input; `CSI 21 t` is not answered. OSC 0/2 titles are stripped of C0/C1 controls, length-capped and rendered as text only.
- BR-15 tmux. Nexus sessions run in remote tmux (SESSION_PERSISTENCE.md §1). OSC 133 inside a pane is not relied upon to reach the client: per S11/S12 it may not work, and forwarding needs `allow-passthrough on` which lets any pane program emit arbitrary escapes to the outer terminal (and tmux can undo passthrough state, S12). `[S13: tmux 3.4+ consumes OSC 133 for prompt navigation, 3.7a fires hook events from it, so tmux hooks are driven by pane-stream bytes and passive content (`cat evil.txt`) can forge them: record in ADR comparison. UNVERIFIED-LOCAL: forwarding to the client and older versions dropping it; no tmux/container runtime exists in this run's sandbox, so TC-21 must confirm.]` **Proposed decision:** `allow-passthrough off` (default); the shell integration inside the pane writes authenticated block events (A/B/C/D + cwd, exit, command id, nonce) to a **side channel**, a per-session append-only file/FIFO under a 0700 dir (`$XDG_RUNTIME_DIR/nexus/<session>/events`, fallback `~/.cache/nexus/…`) read by the connector over a separate SSH exec channel. Block records therefore do not depend on the pane byte stream. On reattach, tmux redraws the screen without markers; blocks are rebuilt from the event log (with a stored byte offset per block into a connector-side output ring, or marked "output unavailable" when the ring has expired), not from the redrawn screen. Alternative if the side channel is rejected: tmux hooks (`pane-*`/`alert-*`) plus `pipe-pane`; to be compared in the ADR. Side-channel hardening: (a) the log holds `cmdline` and cwd, so it is a secret-persistence site: file mode 0600 in the 0700 dir, deleted on session end (and by the connector on teardown), bounded retention while the session lives, and cmdline/cwd are redacted by the connector's redaction pipeline before the connector stores or forwards anything; the log is included in TC-07's canary grep. (b) Its protection comes from **write access** (terminal output cannot write files), not from a nonce; same-user processes can read the dir, so entries carry **no nonce**, only a non-reversible per-entry tag (HMAC of the entry under a key the connector holds and the shell never sees where feasible) or just a sequence number; the BR-12 nonce never touches the log. Same-user malware able to write the file is out of scope. (c) The separate SSH exec channel is authorized and audited under the same session identity and role as the PTY (TELEPORT_IDENTITY_ACCESS), runs exactly one fixed read-only command (tail of the events file; never free-form exec), and is revoked together with the session (role revocation / reattach authorization: NX3-111).
- BR-16 Input routing. State machine of §5 gates all input: only in INPUT (after `B`, before `C`) are keystrokes captured into the draft. In RUNNING (after `C`, before `D`) and in any state where markers are missing/UNKNOWN, keystrokes go straight to the PTY and are never captured into the draft, history, suggestions or AI context. Ctrl+C is always delivered as `0x03`, Ctrl+D as `0x04`, Ctrl+Z as `0x1a` in RUNNING/UNKNOWN, never intercepted by the editor in RUNNING. In INPUT with a non-empty draft, Ctrl+C clears the draft (and sends `0x03` only if the draft is empty), Ctrl+D deletes the char under the cursor and sends `0x04` only if the draft is empty and after a confirm (see TC-26); (the editor's own copy shortcut uses Ctrl+Shift+C / Cmd+C). This covers `read -p`, `apt` Y/n, `python3` REPL, `cat` waiting on stdin, and `sudo`/`ssh`/`su`/`mysql -p` secret prompts.
- BR-13 Redaction before preview/notification/LLM; no terminal text to AI without explicit policy+consent.

## 5. OSC 133 marker model (S4; S8 to confirm)
`A` prompt start → `B` prompt end/input start → `C` output start (command executing) → `D;<exit>` command end. kitty options: `k=s` (secondary prompt/PS2), `cmdline`/`cmdline_url` (S4); `aid`, `cl` `[UNVERIFIED: S8]` (not in S4). State machine: `PROMPT(A) → INPUT(B) → RUNNING(C) → PROMPT(D→A)`. The Nexus integration MUST always emit `B`; if `B` is missing the state is UNKNOWN and no draft is captured (BR-16), keystrokes go raw to the PTY. Duplicate/out-of-order markers ⇒ reset to UNKNOWN and drop grouping for that block. Shells: bash (via PROMPT_COMMAND/DEBUG trap — Warp notes bash needs preexec shim, S3), zsh (precmd/preexec), fish (events). Support matrix to be proven in tests.

## 6. Mode switching: SMART_INPUT ↔ INTERACTIVE_PTY
Safety is structural (BR-16): draft capture exists only in INPUT state. Everything below decides UX (editor visible vs hidden), not whether secrets are captured.
Enter INTERACTIVE_PTY when ANY: (a) DECSET 1049/1047/47 alt-screen set; (b) DECSET 1000–1006 mouse reporting on; (c) RUNNING for more than N = 500 ms `[INFERENCE: initial value]` with no `A`/`D` marker and the foreground command not known to be line-oriented; the prototype must measure false positive/negative rates over the TC-08/TC-22 command set (vim, top, less, apt, python3, read, cat, sleep, ssh) and adjust N; (d) UX hint only: output tail matches a password-prompt regex (`[Pp]assword|passphrase|Passwort|\[sudo\]`), which shows a "secret input" indicator; a non-match does NOT make capture unsafe; (e) user manual toggle (Ctrl+Shift+T, configurable).
Return to SMART_INPUT when: alt-screen reset AND next authenticated `A/B`; or user toggle; or "Reset prompt detection".
In INTERACTIVE_PTY and RUNNING: all keys incl. Esc, Ctrl combos, mouse and resize (SIGWINCH via PTY resize) go to xterm.js untouched; editor hidden or inert. Nested `ssh`, vim, nano, top, less, tmux-in-tmux, `bash -x`: raw. If detection is wrong, the toggle must remain reachable and never be captured by the app.
Nested ssh prints no authenticated markers from the inner shell ⇒ stays raw unless inner integration installed.

## 7. Threat model / negative tests (controlled fixtures only)
Forged OSC 133/633/OSC 8 from `cat evil.txt`; nonce replay (leaked from earlier output) and nonce read from child env; HTML/JS in output; title-set sequences; OSC 52 read/write; query responses (DA/DSR, `CSI 21 t`, DECRQSS, OSC 10/11) triggering PTY-input injection; over-long OSC; paste with `ESC[201~` (bracketed-paste breakout) and Trojan Source characters; secret prompts that evade the password regex; tmux passthrough abuse.
